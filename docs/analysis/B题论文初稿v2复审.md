## Review 报告

### 1. 总体判断：有竞争力，但要避免“看起来像拼接版本”

当前论文的最大竞争力是：你不是只给一个启发式排程，而是给了 MILP 可行最优解，并补了 Q2 双瓶颈资源松弛下界、Q3/Q4 的 C 车间关键链下界和 Q4 显式采购模型。draft 摘要中已经明确说明了“27 个工序实例、41 个设备子任务、MILP、CP-SAT 交叉验证、Q1-Q4 最优时长”等核心结论，这是一个很强的校赛答卷骨架。

如果按校赛论文常见水平评估，当前版本大致可以达到 80–85 分区间；修正下面列出的硬伤后，有机会到 88 分以上。它的核心竞争力不是算法花哨，而是“可证明最优 + 结果可复现 + 解释清楚”。这比单纯遗传算法、模拟退火、贪心调度更容易打动评委。

但现在还存在一个风险：README、论文、代码组织之间仍保留了“原计划用 GA/CP-SAT、v1 用 MILP、当前 draft 用 MILP+CP-SAT”的历史痕迹。README 中子问题策略表仍写 Q2 用遗传算法、Q3 扩展 GA、Q4 外层枚举瓶颈设备 + 内层 GA；但 draft 正文实际把 MILP/HiGHS 作为完整调度主模型，把 CP-SAT 作为验证模型。 这一点必须统一，否则评委或队友会觉得方法路线不稳定。

### 2. 论文层面的优点

第一，问题抽象准确。论文把题目归纳为柔性作业车间调度、资源受限项目调度、序列相关转运时间三者结合的问题，这个定位是合理的。draft 中对车间工序链、设备可替代、双设备协同、跨车间运输和采购预算的表述基本覆盖题目核心约束。

第二，结果表清楚。Q1=41600s、Q2=163764s、Q3=123844s、Q4=123844s，且都给出了“最优性依据”，表格很适合作为正文核心结果。

第三，Q2 的证明思路有区分度。你不是仅说“求解器显示 optimal”，而是构造了只保留高速抛光机和自动传感多功能机冲突的松弛问题，得到与完整可行解相同的下界 163764s。这个上下界夹逼证明很适合写进论文亮点。

第四，Q4 的“不采购”结论不是简单拍脑袋。分析文档说明 CP-SAT 显式采购模型在 128 台候选设备、96 台候选增购设备、1092 个分配变量、4208 个排序变量下得到最优工期 123844s，且最小采购费用为 0 元。 这个结论虽然反直觉，但解释得通：Q3 已达到 C 车间关键链下界，增加设备不能缩短单工序处理时间，也不能打破 C 车间内部顺序。

### 3. 论文层面的主要问题与修改建议

最需要改的是“方法主线统一”。现在 README 说主计划是 OR-Tools CP-SAT + DEAP，GA 仍被写成 Q2-Q4 的推荐解法；但论文初稿已经选择 MILP 为主模型、CP-SAT 为验证模型。 建议正式稿统一改成：

“本文以 MILP 精确调度模型作为主模型，使用 CP-SAT 构造独立下界与采购验证模型；遗传算法仅作为可扩展大规模问题的推广方向，不作为本文结果来源。”

README 也要同步修改。否则论文、代码和项目说明不一致，是校赛中很容易被扣分的地方。

第二，摘要过长，且略显“把所有内容都塞进去”。摘要现在信息量很大，但竞赛论文摘要应更像“问题—方法—结果—结论”的压缩版。建议把摘要控制在 350–450 字，保留四个数值结果和最优性证明链，不要过多解释 CP-SAT/MILP 分工。

第三，参考文献不合格。当前参考文献只有作者和题名，缺少年份、期刊/会议、卷期页码或访问日期。draft 末尾的 [1]–[5] 现在像内部笔记，不像正式论文引用。 建议至少改成 GB/T 7714 风格，尤其是 SciPy、OR-Tools 文档要写访问日期。否则评委会认为“调研深度不足”。

第四，模型公式还不够完整。正文给了目标函数、唯一分配、工序链、初始到达、同设备互斥等核心约束，但 big-M 线性化没有完整展开。既然你的竞争力来自“精确模型”，建议增加一节“同设备排序约束的线性化”，把如下逻辑写完整：

当 `x_{a,m}=x_{b,m}=1` 时，若 `y_{a,b,m}=1`，则 `a` 在 `b` 前；否则 `b` 在 `a` 前。并说明 big-M 足够大，例如取大于全部工序作业时间与最大运输时间之和的上界。

第五，Q2 的“全局最优”要加限定语。你已经在 draft 中写了“在本文双设备同步协同模型下最优”，这是正确的。 但正文后面所有出现“Q2 全局最优”的地方都应统一加一句：“该结论基于双设备同一开始时刻投入、设备完成自身作业后可释放的解释。”否则如果评委按异步协同理解题目，可能会质疑。

第六，图形可复现性是短板。draft 自己承认当前脚本能复现数值结果和结果表，但甘特图尚未纳入统一可复现脚本。 这点必须改。建议新增：

`code/plot/plot_gantt.py`

并让它读取 `baseline_v1/results/*.csv`，生成 `docs/figures/gantt_q1.png` 到 `gantt_q4.png` 以及 `makespan_summary.png`。正式报告中不要写“当前版本未将绘图过程脚本化”，这会主动暴露弱点。

### 4. 代码库层面的审查

`model_solver.py` 的核心建模是比较干净的。数据在 `PROCESS_BASE` 中硬编码，C3-C5 在 `build_processes()` 中展开为三轮，持续时间使用 `ceil(workload / rate * 3600)` 计算。 设备数量、价格、距离、速度等也集中定义，便于检查。

MILP 的变量结构合理：工序开始时间、makespan、设备分配变量 `x`、同设备排序变量 `y`。代码中对每个设备子任务建立唯一分配约束，对车间内部相邻工序建立顺序约束，并对每个工序建立完工时间约束。 同设备不重叠和跨车间转运用 big-M 约束表达，整体逻辑与论文一致。

但是代码库存在四个应修正点。

第一，Q4 在 `model_solver.py` 中不是显式求解，而是直接复用 Q3，并基于关键路径下界令采购为 0。代码注释也明确写了“Q4 由关键路径下界证明追加设备不能进一步缩短工期”。 这本身没错，但论文又写“显式采购模型验证”。因此正式复现命令应把 `verify_optimality_chain.py` 也纳入主复现流程，而不是只运行 `baseline_v1/code/model_solver.py`。

第二，`verify_optimality_chain.py` 的“独立验证”并非完全独立。它从 `baseline_v1.code.model_solver` 导入 `BASE_COUNTS`、`EQUIPMENT_TYPES`、`build_processes`、`travel_time` 等数据和函数。 这意味着它独立于 MILP 求解器，但不独立于数据预处理。论文中不要写“完全独立验证”，应写“独立于 MILP 求解器的 CP-SAT 验证模型”。

第三，`verify_optimality_chain.py` 里硬编码了 `Q2_BASELINE = 163_764` 和 `Q3_Q4_BASELINE = 123_844`。 这不会破坏 CP-SAT 求得 objective 的正确性，但会让验证脚本看起来有“对答案”的痕迹。建议改成从 `baseline_v1/results/summary.csv` 读取基线结果，或者把硬编码常量只用于打印 comparison，不参与模型构建，并在注释里说明。

第四，求解状态没有强制断言。比如 Q4 CP-SAT 第一阶段和第二阶段在代码中只要 `OPTIMAL` 或 `FEASIBLE` 都会继续处理。 正式竞赛代码建议加入：

```python
assert status == cp_model.OPTIMAL
assert status2 == cp_model.OPTIMAL
```

或者至少输出失败并退出。否则在别的电脑上如果只找到可行解但没证明最优，脚本仍可能打印类似“objective”的结果，影响可信度。

### 5. README 与项目结构需要立即修正

README 当前有明显的“历史计划残留”。例如项目结构写了 `code/Q1_单车间调度/`、`code/Q2_多车间调度/`、`code/solvers/` 等目录规划，但从当前 review 可确认的关键可复现代码主要是 `baseline_v1/code/model_solver.py` 和 `code/analysis/verify_optimality_chain.py`。README 同时又说 `baseline_v1` 是“参考”，但论文实际基底就是这个 v1 结果。

建议 README 改成三层：

`code/analysis/verify_optimality_chain.py`：验证 Q2 下界与 Q4 显式采购模型。

第二层：论文文档

`docs/analysis/B题完整分析链与最优性验证.md`：证明链。

第三层：扩展算法
GA、SA、DEAP 只保留为“后续扩展”，不要再放在当前主路线里。

### 6. 在校赛中的优势与风险

优势很明确：

一是结果硬。四问都有数值结果，Q1-Q4 结果表完整，并且有调度表、采购表、甘特图。二是证明链强。Q1 链下界，Q2 双瓶颈松弛下界，Q3 C 链下界，Q4 C 链下界 + 显式采购模型，这套结构在校赛里有明显区分度。三是工程可复现性比普通论文好。README 给出了复现命令，`requirements.txt` 也列出了 scipy、ortools、python-docx、matplotlib 等依赖。

风险也明确：

一是方法路线不统一。README 仍写 GA 主力，而论文用 MILP/CP-SAT。这个必须修。二是“不采购”结论容易被质疑，因为它不符合直觉。你必须把 C 车间关键链下界写得非常清楚，并强调“采购不改变单台设备效率、不改变工序顺序、不允许多人压缩同一工序工程量”。三是图和代码还没有完全闭环。四是文献格式偏弱，会显得“深度调研”不够。

### 8. 推荐的最终论文定位

不要把论文定位成“我们设计了很多算法”。更强的定位是：

“针对小规模但约束复杂的多车间协同调度问题，本文构建可解释的精确优化模型，并通过下界模型证明四个子问题的全局最优性。”

这比“用了 MILP、CP-SAT、GA、SA 很多方法”更干净，也更有说服力。

最终建议标题可以改为：

《基于混合整数规划与关键瓶颈下界的多工序协同作业优化研究》

或者：

《带转运时间的多资源协同调度建模与最优性验证》
